SAP CPI CASE STUDY

Employee Lifecycle Notifications Integration

SAP CPI integration supporting automated employee lifecycle notifications from SAP SuccessFactors Employee Central to downstream IT and logistics processes.

SAP CPI SAP SuccessFactors Employee Central Compound Employee OData Integration Events
01. Overview

Project Overview

This project involved the development of an SAP CPI integration to process employee lifecycle notifications from SAP SuccessFactors Employee Central.

The solution supports multiple HR scenarios, including employee arrivals, departures, preferred name changes and organizational transfers.

Different processing mechanisms are used depending on the type of employee change. Arrival and Departure notifications are event-driven and include specific handling for retroactive employee changes, while Name Change and Transfer scenarios are identified through employee data changes based on lastModifiedDateTime.

SAP CPI retrieves and evaluates the required employee information from SuccessFactors, applies the corresponding business rules and determines whether a notification should be sent to the downstream system.

02. Notification Types

Employee Lifecycle Events

The integration processes four main employee lifecycle notification types.

Arrival — A01

An Arrival notification is generated when a new employee joins the organization or when a former employee is rehired.

The purpose is to allow downstream IT and logistics processes to prepare the required access and workplace activities before the employee's first working day.

The integration also handles retroactive employee scenarios to ensure that relevant arrivals registered or modified retrospectively can still be processed.

Departure — A02

A Departure notification is generated when an active employee leaves the organization or when a planned employee will no longer join.

The notification supports downstream access revocation and offboarding activities.

Retroactive employee changes are also handled so that relevant departure events are not missed when HR information is registered or modified retrospectively.

Name Change — A03

A Name Change notification is generated when an employee's preferred name changes.

Changes to the legal name alone do not trigger a notification when the preferred name remains unchanged.

SAP CPI identifies potentially relevant records using lastModifiedDateTime and then compares the current and previous employee records using Compound Employee.

Transfer — A04

A Transfer notification is generated when an employee changes organizational assignment, such as team, department, division, location, company or other relevant organizational movements.

SAP CPI identifies potentially modified employees using lastModifiedDateTime and compares the current and previous employee records to determine whether the relevant organizational information has changed.

03. Processing Strategy

Event-Driven & Change-Based Processing

Arrival & Departure

Arrival and Departure are processed based on events generated from SAP SuccessFactors.

The integration also includes logic for retroactive employee changes, ensuring that relevant onboarding and offboarding scenarios can still be processed when employee information is registered or modified retrospectively.

Name Change & Transfer

Name Change and Transfer follow a change-detection approach.

lastModifiedDateTime is used to identify employees with potentially relevant modifications. SAP CPI then retrieves the employee information through Compound Employee and compares the current record with the previous record.

If a relevant change is detected, processing continues. If no relevant change is found, the integration terminates without generating a notification.

Modified Employee → Compound Employee → Compare Current vs Previous → Relevant Change? → Continue / End
04. Compound Employee API

Current vs Previous Record Comparison

Compound Employee plays an important role in the change-detection logic used for Name Change and Transfer processing.

SAP CPI retrieves the employee information and compares the current record with the previous record to determine whether the specific field associated with each notification branch has changed.

Expected Field Change Detected

For each processing branch, SAP CPI checks the corresponding field, such as Preferred Name or Cost Center. If that field has changed, the integration continues processing and sends the notification associated with that branch.

No Expected Field Change

If the field associated with the branch has not changed, processing for that branch ends and no notification is generated.

This approach ensures that information is sent only when the specific field being monitored has actually changed.

05. Technical Highlights

Key Technical Features

Event-Driven Processing

Processing of Arrival and Departure scenarios based on SuccessFactors events.

Retroactive Employee Handling

Additional processing logic for Arrival and Departure scenarios involving employee changes registered retrospectively.

lastModifiedDateTime Detection

Identification of potentially modified employees for Name Change and Transfer processing.

Compound Employee Comparison

Comparison between current and previous employee records to determine whether a relevant change actually occurred.

Conditional Processing

Continuation of the integration only when the comparison identifies a relevant business change.

Multiple Notification Types

Support for Arrival, Departure, Name Change and Transfer scenarios within the same integration solution.

Selective Notification Processing

Prevention of unnecessary downstream notifications caused by unrelated employee data modifications.
