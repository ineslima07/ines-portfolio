SAP CPI CASE STUDY

Contract & Agreement Automation

SAP CPI integration automating the creation and processing of multiple employee agreements and contractual addendums across SAP SuccessFactors, Icertis and Azure Service Bus.

SAP CPI SAP SuccessFactors Azure Service Bus Icertis OpenText REST APIs OData Data Store
01. Overview

Project Overview

This project involved the development of a SAP CPI integration to automate the creation and processing of employee agreements between SAP SuccessFactors and Icertis.

The solution supports more than 10 different agreement and addendum types, each with its own business rules, data requirements, document structure and variables.

The solution is composed of two main integration flows. The first flow processes pending SuccessFactors workflows and creates the corresponding agreements in Icertis. The second flow receives the agreement result through Azure Service Bus and determines how the SuccessFactors workflow should continue.

02. Architecture

Integration Architecture

SAP CPI acts as the orchestration layer between SAP SuccessFactors, Icertis and Azure Service Bus, coordinating agreement creation, workflow processing and document handling.

SAP SuccessFactors Employee Data · Pending Workflows
↓
SAP CPI Orchestration · Mapping · Transformation · Business Logic
↓
Icertis Agreement Creation & Management
↓
Azure Service Bus Agreement Result Messages
↓
SAP CPI Result Processing · Workflow Control · Document Handling
↓
SAP SuccessFactors / OpenText Workflow & Document Processing
03. Agreement Automation

Multiple Agreement & Addendum Types

One of the main challenges of the integration was supporting more than 10 different agreement and contractual addendum types within the same integration landscape.

Each agreement type has its own business rules, required variables, data requirements and document structure.

SAP CPI applies the appropriate processing logic according to the agreement type, allowing different contractual processes to be handled through the same integration solution.

04. Agreement Creation

SuccessFactors → SAP CPI → Icertis

The first integration flow runs every 10 minutes and retrieves pending workflows from SAP SuccessFactors.

For each workflow, SAP CPI performs multiple calls to SuccessFactors to retrieve the employee, job, workflow and additional information required for agreement creation.

The retrieved data is processed using Value Mapping, XSLT transformations and agreement-specific business logic. SAP CPI then builds the required payload and sends the agreement creation request to Icertis.

After successful creation, the document identifier returned by Icertis is stored in a dedicated custom field in SAP SuccessFactors.

Pending Workflows → Retrieve SF Data → Value Mapping → XSLT → Build Agreement → Icertis
05. Duplicate Prevention

Agreement Tracking in SuccessFactors

Since the integration processes pending workflows every 10 minutes, preventing the same workflow from creating multiple agreements in Icertis was an important requirement.

After an agreement is successfully created, the identifier returned by Icertis is stored in a dedicated custom field in SAP SuccessFactors.

SAP CPI uses this value to identify workflows that have already been processed and prevent the same agreement from being created again in Icertis.

Agreement Created → Store Icertis ID in SuccessFactors → Prevent Duplicate Processing
06. Agreement Result

Azure Service Bus → SAP CPI → SuccessFactors

The second integration flow is event-driven and is triggered by messages received from Azure Service Bus.

SAP CPI processes the received agreement result and determines how the corresponding workflow in SAP SuccessFactors should continue.

Agreement Approved

When an approval result is received, SAP CPI processes the finalized agreement, advances the corresponding SuccessFactors workflow to its next step and stores the document in Employee Central.

The document is subsequently transferred to OpenText through the existing document integration.

Agreement Canceled

When a cancellation result is received, SAP CPI cancels the corresponding workflow in SuccessFactors and the process is terminated.

Azure Service Bus → SAP CPI → Evaluate Result → Approve & Continue / Cancel Workflow
07. Agreement Lifecycle

Agreement Identifier Management

The Icertis document identifier stored during agreement creation is used to maintain the relationship between the SuccessFactors workflow and the corresponding agreement.

When the agreement is successfully completed and the SuccessFactors workflow continues, SAP CPI removes the stored identifier from the custom SuccessFactors field.

Clearing the identifier ensures that a future workflow for the same employee can initiate a new agreement process while still preventing duplicate creation during the current process.

08. Error Handling

Configurable Quarantine Strategy

A key challenge was controlling repeated processing failures in the scheduled integration flow.

Because pending SuccessFactors workflows are processed every 10 minutes, a workflow experiencing an error could otherwise be selected again during every execution, repeatedly generating the same failure and unnecessary error notifications.

To address this, I implemented a configurable quarantine mechanism using SAP CPI Data Store.

When a transaction fails, it is placed in quarantine and temporarily excluded from normal processing. It becomes eligible for processing again only after the configured quarantine period.

The current quarantine period is 24 hours and can be adjusted without modifying or redeploying the integration flow.

09. Operational Resilience

Reducing Repeated Errors

Without Quarantine

A failed workflow could be selected again every 10 minutes, repeatedly causing the same error and generating unnecessary notifications.

With Quarantine

Failed transactions are temporarily stored in the Data Store and excluded from processing until the configured quarantine period has expired.

10. Technical Highlights

Key Technical Features

Multi-Agreement Processing

Support for more than 10 agreement and addendum types with different business rules, structures and variables.

Scheduled Processing

Automated processing of pending SuccessFactors workflows every 10 minutes.

OData Orchestration

Multiple SuccessFactors calls to retrieve and consolidate the data required for agreement creation.

Value Mapping & XSLT

Mapping and transformation of SuccessFactors data into the structures required by each agreement type.

Duplicate Prevention

Agreement identifier tracking in SuccessFactors to prevent duplicate creation in Icertis.

Azure Service Bus

Event-driven processing of agreement results through Azure Service Bus.

Workflow Control

Approval, continuation or cancellation of SuccessFactors workflows according to the agreement result.

Document Handling

Processing of finalized agreement documents for Employee Central and downstream storage in OpenText.

Configurable Quarantine

Data Store-based mechanism to prevent continuous reprocessing of failed workflows.
