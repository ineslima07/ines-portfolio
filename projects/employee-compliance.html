SAP CPI CASE STUDY

Work Permit Integration

Automated integration of employee Work Permit data and documents between an external immigration platform and SAP SuccessFactors.

SAP CPI SAP SuccessFactors Work Permit REST APIs OData Data Store
01. Overview

Project Overview

This project involved the development of an SAP CPI integration to automate the synchronization of employee Work Permit information and associated documents between an external immigration platform and SAP SuccessFactors.

The integration is event-driven. The source platform triggers the process by sending the identifiers required to initiate the integration. SAP CPI then orchestrates the retrieval of the Work Permit data and associated document, processes and transforms the information, and synchronizes it with SAP SuccessFactors.

02. Architecture

Integration Architecture

SAP CPI acts as the integration and orchestration layer, coordinating the communication between the source platform and SAP SuccessFactors through REST and OData services.

03. Work Permit Processing

Event-Driven Processing

The first integration flow is triggered when a Work Permit process reaches the required stage in the source platform.

The initial event contains only the identifiers required to start the integration. SAP CPI uses these identifiers to retrieve the additional Work Permit information and associated document through API calls.

The retrieved information is then validated, transformed and prepared for synchronization with SAP SuccessFactors.

04. Document Processing

Work Permit Document Handling

In addition to the Work Permit data, the integration retrieves the corresponding digital document.

SAP CPI processes the document and associates it with the Work Permit information before completing the synchronization with SAP SuccessFactors.

05. Challenge & Solution

Building a Resilient Integration

Challenge

The integration could be triggered before the employee information required to complete the Work Permit synchronization was available in SAP SuccessFactors.

Solution

A persistence and retry mechanism was implemented using SAP CPI Data Store. Transactions that cannot yet be completed are temporarily persisted instead of failing permanently.

06. Reprocessing

Automated Retry Flow

A second SAP CPI integration flow is responsible for managing pending transactions.

It periodically retrieves stored records and verifies whether the information required to continue processing has become available.

Once the required employee information is available, the Work Permit synchronization continues automatically. Successfully processed transactions are then removed from the pending store.

07. Technical Highlights

Key Technical Features

API Orchestration

Coordination of multiple REST API calls to retrieve the Work Permit information required for processing.

Data Transformation

Transformation and mapping of Work Permit data into structures compatible with SAP SuccessFactors.

Document Handling

Retrieval and processing of Work Permit documents as part of the employee data synchronization process.

Persistence & Retry

SAP CPI Data Store capabilities used to safely manage transactions that require later reprocessing.
